## What it is `✅ VERIFIED`

Two appearance styles, **Focused** (calm/formal — what the app already looks like) and **Playful** (Gen Z: bold ink borders, offset "shelf" shadows, sticker badges like `+20 XP PER SECTION` / `MEET YOUR CAREER BUDDY`, cream right panel, sparkles). Figma component note on `GTH · Style switch` (`7875:85654`): _"Appearance style for talent screens. Independent from Switch Modes (AI chat vs step-by-step) and from Accessibility settings."_ Same features and data — only the look/wording differs.

## THE RULES (every Playful edit must obey)

1. **Never change a Focused value.** Playful styling is added ONLY as `playful:`-prefixed classes (e.g. `rounded-[12px] playful:rounded-[16px] playful:border-[1.5px]`) or inside a branch gated on `useUiStyle().uiStyle === 'playful'`. Do not edit, remove or reorder an existing un-prefixed class to make Playful work.
2. **Shared components** (`Button`, `Modal`, `Toast`, `ChatThread`, `TalentProfilePanel`, `EngagementTop*`…) are used by other screens. Add `playful:` classes only; the scope guarantees they don't apply elsewhere. Wording changes (Playful copy differs) go through a prop or a data lookup, never by editing the Focused string.
3. **Structure differences** (different DOM in Playful): render a separate component/branch gated on `uiStyle === 'playful'`; keep the Focused branch byte-for-byte.
4. **Text is verbatim from Figma `characters`.** Playful copy often differs from Focused — pull it from the Playful frames, do not reuse or invent.
5. **Don't edit `src/index.css`.** Put shared Playful tokens in `src/styles/playful.css` (append under your own `/* === <agent> === */` header; never reorder others' blocks).
6. **File ownership**: edit only the files you were assigned. Need a change elsewhere → list it in your report ("requests"); the lead applies it. `CareerBuddySection.jsx` is edited only by the Shell agent.
7. **Verification** (see below) is mandatory; Focused must still match the desktop baselines.

## Accessibility bar (non-colour; see the colour rule below)

- **COLOURS ARE FIGMA-EXACT (owner decision 2026-10-16, overrides everything below on colour).** Never change a text/border/fill/icon/gradient/shadow colour to improve contrast; report low-contrast Figma pairs as FYI only. "Accessibility" for this owner means responsive LAYOUT behaviour, not recolouring. Non-visual a11y (ARIA, focus management, keyboard, reduced-motion) stays; never add invented visible or sr-only copy.
- Never rely on colour alone (XP/“done” states need text/icon). Visible focus ring on every interactive element (≥ 2px, ≥ 3:1) — the heavy ink borders must not hide it.
- Motion (sticker wiggle, confetti, sparkle twinkle, XP pop): wrap in `motion-safe:`; no information only in motion; nothing flashes > 3×/s.
- Dialogs/overlays: `role="dialog"`/`aria-modal`, labelled, focus moves in and is restored, Esc closes, background inert. Toasts: success/info `role="status"`, error/warning `role="alert"`, not auto-dismissed faster than 6s, dismissible.
- Live chat: new messages announced politely; icon-only buttons have `aria-label`; decorative art `aria-hidden`; touch targets ≥ 44px visual-or-hit on phones.
- Switch: radiogroup semantics (done). Respect `prefers-reduced-motion`, `forced-colors` (borders must remain visible).
